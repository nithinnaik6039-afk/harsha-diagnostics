1. EXECUTIVE SUMMARY & BUSINESS MODEL
================================================================================
Harsha Diagnostics is an on-demand, hyper-local diagnostic laboratory ecosystem
designed to provide certified diagnostic testing directly at patient doorsteps.

Key Value Propositions:
- Patients can book diagnostic blood, urine, and pathology tests in under 60 seconds.
- AI-powered dispatch algorithm assigns nearby Certified Medical Laboratory
  Technicians (MLTs) / Phlebotomists based on geo-proximity and inventory availability.
- Real-time GPS tracking allows patients to track the arrival of phlebotomists on a live map.
- Cold-chain monitoring ensures sample vials are maintained within clinical temperature
  thresholds (2°C - 8°C) from collection to laboratory handover.
- Automated report delivery directly to the customer app with visual Smart Health
  Indicator charts (Normal, Borderline, Critical).
- Multi-lingual user interface with native Telugu and English support for maximum
  accessibility across urban and rural demographics.

2. SYSTEM ARCHITECTURE & TECH STACK
================================================================================
The platform follows a unified modular architecture:

A. BACKEND SERVICES

3. BACKEND API & REAL-TIME WEBSOCKET SYSTEM
================================================================================
The backend server (`server.js`) operates on port 5005 (configurable) and coordinates:
- RESTful HTTP APIs for authentication, test catalog, booking, payments, and certificates.
- Socket.io room-based messaging for live telemetry:
  - `join-room`: Subscribes clients to specific order rooms (e.g. `order_<id>`).
  - `update-location`: MLT mobile app emits GPS coords (`lat`, `lng`, `mltId`, `orderId`).
  - `location-broadcast`: Broadcasts current phlebotomist position to the tracking customer.
- Resilient Graceful Mock Fallback: In development/offline environments without MongoDB,
  the server automatically boots in mock mode so interfaces remain interactive.

4. DATABASE DESIGN & DATA MODELS
================================================================================
The database consists of 9 core schemas:

1. User Schema (`User.js`):
   - Fields: `name`, `email`, `phone` (unique index), `role` ('customer' | 'admin'),
     `addresses` (array of labeled addresses with lat/lng), `pushToken`, `avatarUrl`,
     `medicalHistory` (allergies, diabetic, chronic conditions).

2. MLT (Phlebotomist) Schema (`MLT.js`):
   - Fields: `name`, `phone`, `email`, `rating` (default 4.8), `totalCollections`,
     `isOnline` (boolean), `location` (GeoJSON Point: [lng, lat] with 2dsphere index),
     `kycStatus` ('pending' | 'verified' | 'rejected'), `vehicleNumber`, `vaccinationStatus`.

3. Test Schema (`Test.js`):
   - Fields: `name`, `code`, `category` ('Sugar'|'Thyroid'|'Lipid'|'Liver'|'Infection'|'Vitamins'|'Bundles'),
     `price`, `discountPrice`, `fastingRequired` (boolean), `sampleType` ('Blood'|'Serum'|'Plasma'|'Urine'),
     `tatHours` (Turnaround time), `tubeType` ('Lavender EDTA'|'Red Plain'|'Grey Fluoride'|'Yellow SST'),
     `description_en`, `description_te`.

4. Order Schema (`Order.js`):
   - Fields: `orderId` (e.g., HD-2026-XXXX), `customer` (User ref), `patientDetails` (name, age, gender),
     `address` (street, city, lat, lng, pincode), `slot` (date, timeSlot),
     `tests` (array of Test refs), `totalAmount`, `paymentStatus` ('pending'|'paid'|'failed'|'cash_on_collection'),
     `paymentMethod` ('razorpay'|'cod'|'upi'), `orderStatus` ('pending'|'assigned'|'en_route'|'arrived'|'sample_collected'|'in_lab'|'completed'|'cancelled'),
     `assignedMLT` (MLT ref), `vialBarcodes` (array of strings), `temperatureLog` (array of readings),
     `reportUrl`, `digitalSignature`, `rating`.

5. Certificate Schema (`Certificate.js`):
   - Fields: `certificateName`, `issuingBody` (NABL / ISO / ICMR), `licenseNumber`,
     `validUntil`, `verificationUrl`, `documentUrl`.

6. Partner Schema (`Partner.js`):
   - Fields: `clinicName`, `doctorName`, `referralCode`, `commissionRate`, `payoutPhone`.

7. ServiceZone Schema (`ServiceZone.js`):
   - Fields: `zoneName`, `polygon` (GeoJSON Polygon), `isActive`, `baseDeliveryFee`.

8. DelayEvent Schema (`DelayEvent.js`):
   - Fields: `orderId`, `reason` (Traffic, Weather, Patient Delay), `delayMinutes`, `reportedAt`.

9. ChatbotFAQ Schema (`ChatbotFAQ.js`):
   - Fields: `query_pattern`, `response_en`, `response_te`, `category`.

6. APPLICATION 2: MLT PHLEBOTOMIST APP
================================================================================
Target Audience: Certified Phlebotomists, Field Lab Technicians
Path: `mlt-app/`
Package: `com.harshadiagnostics.mlt`

Key Features & Operational Modules:
1. Shift Management & Duty Toggle (`index.tsx`):
   - 1-tap "Go Online / Offline" toggle.
   - Background GPS location broadcaster to backend dispatch radar.
2. Instant Incoming Dispatch Alert (`incoming-alert.tsx`):
   - Full-screen audio-visual modal when a new home sample collection is assigned.
   - Displays patient distance, test count, payment mode, and accept/decline action within 30s.
3. Multi-Stop Route Optimizer (`MultiStopRouteOptimizer.tsx`):
   - Sequences all daily appointments using shortest-path TSP algorithms.
4. Tube Collection & Color Guide (`TubeCollectionGuide.tsx`):
   - Visual reference of vacutainer tube caps:
     * Lavender EDTA : Complete Blood Count (CBC), HbA1c
     * Red / Yellow SST: Liver Function, Lipid Profile, Thyroid, Hormones
     * Grey Fluoride: Fasting Blood Sugar, Oral Glucose
     * Blue Citrate: Coagulation, PT/INR
5. Cold-Chain Temperature Monitor (`ColdChainMonitor.tsx`):
   - Continuous sample temperature tracking. Alerts technician if cooler exceeds 8°C.
6. Thermal Degradation AI (`ThermalDegradationAI.tsx`):
   - Estimates biological sample degradation risk based on elapsed time and ambient temperature.
7. Vein Scanner HUD (`VeinScannerHUD.tsx`):
   - Camera-assisted high-contrast color filter overlay to assist in difficult pediatric and geriatric vein location.
8. Digital Signature & Consent Pad (`DigitalSignaturePad.tsx`):
   - Collects patient digital touch signature before phlebotomy puncture.
9. Barcode & Tube QR Scanner (`OrderQRCode.tsx`, `ChainOfCustodyAudit.tsx`):
   - Scans barcode sticker placed on each vial to bind sample tube ID with patient order.
10. Biohazard Waste Audit (`BiohazardWasteAudit.tsx`):
    - Compliance checklist for sharps container disposal and yellow biohazard bag sealing.
11. Emergency SOS Modal (`EmergencySOSModal.tsx`):
    - Instant 1-tap distress signal broadcasting coordinates to Admin dispatch center.
12. Offline Sync Engine (`OfflineSyncBanner.tsx`):
    - Complete local SQLite/AsyncStorage queuing for rural areas with zero cellular connectivity.

8. ADVANCED CLINICAL & AI MODULES
================================================================================
1. Optical Character Recognition (OCR) Engine:
   - Parses handwritten and printed doctor prescriptions to automatically extract test names.
2. AI Pre-Analytical Error Prevention:
   - Detects hemolyzed, lipemic, or insufficient volume warnings prior to laboratory submission.
3. Critical Panic Value Alert System:
   - Automatically detects severe out-of-range lab results (e.g. Potassium > 6.0 mEq/L, Platelets < 20,000)
     and sends high-priority SMS/push notifications to treating physicians.
4. Smart Thermal Degradation Calculator:
   - Algorithm calculates biological sample half-life degradation based on ambient Indian summer temperatures.

9. SECURITY, PRIVACY & COMPLIANCE
================================================================================
1. Patient Data Encryption:
   - HTTPS / TLS 1.3 enforced for all client-server communications.
   - Medical reports and sensitive health indicators encrypted at rest.
2. Phone Number Masking (`PatientCommunicationMask.tsx`):
   - Phlebotomists call patients via masked virtual numbers to protect patient phone numbers.
3. Role-Based Access Control (RBAC):
   - JWT middleware strictly limits access based on user roles (`customer`, `mlt`, `admin`).
4. NABL / ISO Guidelines Compliance:
   - Strict adherence to NABL 112 (Specific Criteria for Accreditation of Medical Laboratories).
   - Biomedical Waste Management Rules, 2016 barcoded tracking.

12. COMPLETE REST API ENDPOINT REFERENCE
================================================================================
AUTH ENDPOINTS (`/api/auth`):
- POST /api/auth/send-otp          : Send 6-digit OTP to mobile phone
- POST /api/auth/verify-otp        : Verify OTP and return JWT token
- POST /api/auth/register          : Register new customer or MLT
- POST /api/auth/firebase-google   : Google OAuth SSO sign-in
- GET  /api/auth/profile           : Fetch logged-in user profile [Bearer Token]
- PATCH /api/auth/push-token       : Register Expo push notification token

TEST ENDPOINTS (`/api/tests`):
- GET  /api/tests                  : List all diagnostic tests and categories
- POST /api/tests                  : Create new test [Admin only]
- PUT  /api/tests/:id              : Update test details & pricing [Admin only]
- DELETE /api/tests/:id            : Archive test [Admin only]

ORDER ENDPOINTS (`/api/orders`):
- GET  /api/orders                 : Fetch user orders or all orders for Admin/MLT
- GET  /api/orders/:id             : Fetch single order details and milestone log
- POST /api/orders                 : Create new diagnostic home collection order
- PATCH /api/orders/:id/status     : Transition order status (Assigned, In-Lab, etc.)
- PATCH /api/orders/:id/assign     : Assign phlebotomist to order [Admin/Auto-dispatch]
- PATCH /api/orders/:id/decline    : Decline dispatch assignment [MLT only]

PAYMENT ENDPOINTS (`/api/payments`):
- POST /api/payments/create-order  : Create Razorpay transaction order
- POST /api/payments/verify        : Verify HMAC-SHA256 Razorpay payment signature
- POST /api/payments/confirm-direct: Confirm Cash-on-Collection / Direct payment
